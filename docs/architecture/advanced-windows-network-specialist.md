# Advanced Windows and Network Specialist

The specialist starts only after tenant-scoped employee/device resolution and granted diagnostic consent. It follows a layered read-only path instead of jumping directly to a repair: Windows build and inventory, services and processes, bounded Event Log windows, resource pressure, Windows Update, adapter/link state, IP/DHCP/gateway/routes, DNS, proxy, VPN, firewall policy state, and a target-specific protocol or port test.

Windows and network paths are distinct. A network case must identify the active connection type before diagnostics begin. The agent never receives unrestricted shell or PowerShell access, never collects Wi-Fi keys, VPN secrets, credentials, or private keys, and cannot disable or bypass firewall, endpoint security, or enterprise policy. Firewall inspection is evidence-only.

RAG requests are filtered by tenant permission, Windows version and build, connection type, VPN expectation, and the affected business function. Every root-cause hypothesis must cite evidence identifiers. Weak evidence returns to clarification; close high-confidence causes preserve the contradiction for human review rather than hiding it.

Remediation remains proposal-only. Persistent service, adapter, driver, update, DNS, proxy, VPN, route, firewall, or policy changes require qualified independent approval, captured pre-state, a specific rollback method, and governed execution outside the specialist. Closure requires verified technical state, restoration of the original Outlook, printing, scanning, or endpoint function, and explicit employee confirmation. Hardware/link failure, site or provider outage, enterprise policy, security, identity/certificate, and admin-only update or driver work escalate to the responsible team.
