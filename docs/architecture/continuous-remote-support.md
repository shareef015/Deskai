# Continuous conversation and consent-gated UI support

The support conversation remains active from greeting through employee verification. Intake collects the problem, device and symptom details with visible follow-up questions. Only after the device and issue are understood does DeskPilot request short-lived remote-access permission with an explicit purpose, device, capability list and decline option.

Remote permission authorizes a scoped UI-mode session, not repair authority. Read-only visual diagnostics happen first; any change requires a separate exact repair approval. The employee can revoke access at any time. Technical verification is followed by an employee “is it working?” decision; a negative result continues investigation or escalates instead of claiming resolution.
