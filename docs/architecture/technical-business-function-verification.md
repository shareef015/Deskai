# Technical and Business-Function Verification

Verification begins only after a successful execution result bound to the exact plan fingerprint. The agent reruns a small allowlisted set of bounded read-only checks and records an evidence identifier, expectation, observation, and status for each. It validates the technical state and the original employee business function rather than relying on command exit codes.

Outlook verification exercises the affected launch, connectivity, send/receive, or search path. Printing requires a submitted test page plus confirmed physical output; scanning uses a synthetic privacy-safe artifact without inspecting employee content. Windows and network checks cover the affected service, resource, adapter, DNS, VPN, or target protocol. Separate regression checks detect collateral damage.

Failed or regressed changes route to rollback when supported and otherwise escalate. Unknown evidence returns to bounded diagnosis. Technical success moves to an authenticated employee-confirmation interrupt; it cannot resolve the incident by itself. Confirmation is bound to the same tenant, incident, assigned device, and verification fingerprint. An employee report that the issue remains returns to verification.
